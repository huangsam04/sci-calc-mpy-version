# 绘图反馈分支

用户提交方程后，先在现有 framebuffer 上显示 `Plotting` 和短进度条；每个绘图切片推进真实已完成采样量。OLED 是输出设备，不是额外存储：进度状态只能是固定标量，像素仍只写入既有 8192 B framebuffer。

## 工作项

- [ ] 测量当前从提交方程到首个可见结果的路径，并建立可在主机重复的逐步绘图回放。
- [ ] 复用 Plot 的预建工作对象、`FrameScheduler`、`DamageMap` 和 `Renderer`；将自动缩放和曲线采样拆成有界切片。
- [ ] 在提交后先提交一次进度画面，随后仅损伤进度条所在行；完成或异常时吸附到正确曲线/错误终态。
- [ ] 新输入或离开页面时取消未完成工作，不保留可重建曲线资源，也不调用逐帧 GC。
- [ ] 为首帧反馈、进度单调性、完成、取消和无额外像素缓冲添加聚焦测试。

## 完成条件

- [ ] 复杂方程等待期间始终有可见且真实的进度反馈。
- [ ] 一个 framebuffer、0 B 新像素缓冲、0 稳态逐帧分配和无 `MemoryError` 保持成立。

完成后回到 [PLAN](../PLAN.md) 勾选“绘图反馈”。
